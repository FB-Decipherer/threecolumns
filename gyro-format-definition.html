GYR-O Pages Format Definition

Version 0.27, working draft · 28 October 2026 · Walter Wilkinson · Worland · Washakie County · Wyoming

What a page has to do to be a GYR-O page, what it may do, and what its author brings. Compiled from gyro-sites.online, the README and the project log; where those disagree, the disagreement is listed at the end rather than settled here.

GYR-O Pages is a page format for a single-topic website. Every page presents its topic at three depths, in three columns: A, plain answers; B, the sources; C, how it works. Every source sits in the middle column as a previewed card, and everything below a marked threshold follows the same standard on every GYR-O site.

How to read this

MUST marks what makes a page GYR-O; a page missing one is not a GYR-O page. SHOULD is the default, departed from only for a reason the page states in column C. MAY is optional. Each rule has a number so a site can be audited against it line by line.

The key words MUST, SHOULD and MAY in this document are to be interpreted as described in BCP 14 (RFC 2119, RFC 8174) when, and only when, they appear in all capitals, as shown here. MUST NOT is not yet used; a prohibition is written as a MUST.

The name. The format is called GYR-O Pages. GYR-O, always in capitals and always with its hyphen, is read off the color scheme: Green, Yellow, Red for the three columns readers see, then the hyphen, then Orange for the build and its admin page, which only the builder ever sees. The hyphen is the “sometimes”: GYR-O = Green · Yellow · Red · and sometimes Orange. It also makes the name its own; a plain “gyro” is a sandwich and an instrument. Where the format is named, it is GYR-O Pages; used as a description, plain GYR-O is enough: a GYR-O site, the GYR-O standard.

The class is gyro-sites.online. Every other site is an instance. A rule that proves itself on an instance is written back into the class and the template, so the next site starts with it.

0 · The index page

The threshold (rule 1.4) divides every GYR-O page into two named parts: Intro above it, Info below it. The front page, index.html, is built from that division.

East Bench Farm

Intro · what this site's subject needs: name, standfirst, picture.
Info · the GYR-O standard: control strip, then columns A, B and C.

Working example. Tick either box, or both. No script runs here.

No.LevelRule
0.1MUSTThe index page shows the site's title, exactly two checkboxes and the site's picture as a thumbnail, nothing else. The checkboxes are labeled Intro then Info, in that order. The thumbnail opens the picture full size. The title and the thumbnail both step aside when Intro is on, since Intro opens with the same title and picture.
0.2MUSTStarkly, jarringly austere: white background, black type, and no Dark mode on index.html, whatever the reader's system setting. Dark mode belongs everywhere in Info (rules 7.4 and 9.2).
0.3MUSTChecking Intro shows everything above the threshold; unchecking it hides it. Info does the same for everything below. The two are independent, and both may show at once.
0.4MUSTOn load, Intro is checked and Info is not, so the first view is the site itself, with the GYR-O detail one click away. A link may set the boxes for the reader: #intro, #info, #intro+info or #none.
0.5MUSTThe checkboxes work with scripts off. They are plain CSS checkboxes, as on masthead-system.html.

1 · The shape

No.LevelRule
1.1MUSTOne topic per site. A topic may run as a standing page or as a running series, never as a mixed bag.
1.2MUSTThree columns at three depths, always in the order A, B, C: A plain answers for the newcomer; B every source, previewed, for the checker; C full detail for the specialist. A is always leftmost and C always rightmost.
1.3MUSTThe columns are defined by depth, not by geometry. They are side by side where they fit, stacked on a phone, and given their own pages where one column holds more than a column can (as at worland-dog-law.online). Stacked, paged or side by side, they are still called columns.
1.4MUSTThe threshold divides the page. Above it is Intro: whatever the subject needs, such as name, standfirst, picture. Below it is Info: the GYR-O standard. It is drawn as a double rule, the only doubled line in the family, with the GYR-O mark knocking a gap in it and the caption, in italics, The page layout below is standard on every GYR-O site. Standard, not identical: the structure is the same everywhere, the content is each site's own.
1.5MUSTEvery color, heading, caption and control below the threshold is the same on every GYR-O site. A reader who has used one site already knows where to look on the next: the same colors, the same places, on every site. Stacked on a phone, each column keeps a 6px stripe of its color down its left edge, often the only cue to where the reader is.
1.5aMUSTPosition carries meaning. Every standard element has a standard place, and the page reads from the plainest point, the top of column A, to the most technical, the foot of column C.
1.6SHOULDA single page. Paged form is used only when a column outgrows a column (rule 1.3).

2 · Column A, plain answers

No.LevelRule
2.1MUSTWritten for a reader who knows nothing about the subject: what is this, what does it cost, why should I care.
2.2MUSTEach answer is a native folding element under a question, folded on load.
2.3SHOULDThe sentence that matters sits in the question line or the first line of the answer, because a reader arriving from a search lands on a closed fold.
2.3aMUSTEach answer opens with its plain answer in bold, one sentence, so a reader who stops there has it.
2.3bMUSTPoint of view follows the reader. A client's own site speaks as the client to its customers (we, ours). The class site, the handout and any pitch speak to the prospective owner (you, yours). The same answer, such as why a website as well as Facebook, is written once in each voice, never mixed.
2.4MAYThe first answer may be open on load, as on the tree-service sample, provided column C says so and why.

3 · Column B, sources

The two fixed blocks

No.LevelRule
3.1MUSTColumn B opens with a short key, How to read a card, listing the six parts of a source card in order (rule 3.4), so a reader meets the shape before the cards. Then come two blocks built alike (heading, caption line, then content), one above the other in one column, never side by side.
3.2MUSTInternal links, captioned The two most recent content changes.: two cards, newest first, each a date and what changed, linked to the place on the page where it changed.
3.3MUSTExternal links, below it, captioned Every reference to some other website.: one source card for every other site the page mentions. The headings and both captions are word for word the same on every site.

The source card

No.LevelRule
3.4MUSTSix parts, in this order, every time: 1 number and kind · 2 title · 3 provenance (who made it, when, under what license) · 4 preview (what you would find there) · 5 why it is cited (what it is doing on this page) · 6 the link.
3.5MUSTThe link is last, and only last. A Back button may appear below it; that is a way back, not something the card says.
3.6MUSTPart 5 is written by the citer and says what the source actually supports. Part 4 says what is really there, not the publisher's own blurb.
3.7MUSTOne card per source. Citing it again costs another numeral, not another card.
3.8MAYPart 4 may speak the source's own medium: a baked thumbnail for an image or scan, a first page and page count for a PDF, row and column counts for a dataset. Parts 1, 2, 3, 5 and 6 never change. A thumbnail is used only when part 3 shows reproduction is allowed, and is stored in the page, never fetched at read time.
3.9MUSTA source that has died is marked, not removed: its link is disabled and struck through, with a dated note at the foot of column B.
3.10MUSTLink status is read from a same-site file, links.json, written by whoever ran the check. No file means no claim, never a false alarm. The page never tests other sites from the reader's browser.
3.11MUSTA source that cannot be fetched cannot be previewed, so it cannot be cited. It may still be linked as a plain name.

4 · Column C, how it works

No.LevelRule
4.1MUSTOpens with the lede, word for word: Prior know-how is assumed here, and the items become more technical toward the bottom.
4.2MUSTSections run from least to most technical.
4.3MUSTThe last thing in column C is the Technical Colophon: the essentials of how the page is built and run (format version, file, scripts, fonts, hosting, TLS, domain and DNS, publishing tools, what built and checked it, with versions, what is collected, license, last change), listed without explanation and without defining its terms. Instead each term is underlined as a link to its Wikipedia article, the one place in the format where a link goes straight out rather than to a source card. It is the polar opposite of the first answer in column A.
4.4SHOULDDescribes what the page does rather than telling the reader what to do. Write words are drafted here, not draft the words.

5 · Citation

No.LevelRule
5.1MUSTA claim is cited with a numeral: a small red number on a white disc that links to the card with the same number. Numerals appear only in columns A and C, never in the header. A name in the header may be a plain link.
5.2MUSTEvery reference names what it points at, never where it sits. No ibid., no see above, because a page read out of order has no above.
5.3MUSTBoth directions are one click. A numeral brings its card into view and marks it; a Back button at the card's foot returns to the numeral, outlined in gold; the number on the card itself cycles through every place that cites it.

6 · Transparency

Each of these costs the author something. That cost is the only reason any of them is worth anything.

No.LevelRule
6.1MUSTA defect, once found, is published, not quietly fixed first.
6.2MUSTAn argument that would help but cannot be checked is left out.
6.3MUSTChecks are named, with their count, so the claim can be audited.
6.4MUSTA sample says it is a sample, across the masthead, in a box that cannot be missed.
6.5SHOULDA chronicle, the dated record of every change and why, is linked from column B.
6.6MUSTA feature that would fail toward a false positive is left out. The page would rather say nothing than say something untrue.

7 · Renderings and controls

No.LevelRule
7.1MUSTOne breakpoint. Above it, all three columns show, the two unselected ones dimmed and selectable by a click anywhere in them. Below it, one column at a time with A, B, C acting as tabs. There is no separate mobile site.
7.2MUSTPrinted, the page becomes one document in the order A, B, C, each column starting on a fresh page, every folded answer opened, controls and the masthead picture left out.
7.3MUSTWith scripts off, all three columns still render and read, on a phone and on a desktop.
7.4MUSTThe control strip carries the column tabs, a search box that searches this page only and indexes it at load, Download PDF and Dark. Download PDF hands over a prebuilt PDF file kept beside the page; it never opens the print dialog. A round Top button appears after about a screen of scrolling.
7.5SHOULDPhone view is hidden unless the address carries ?dev. It is shown to every reader only where the layout is the subject, as on the class.
7.6MUSTA real tab set for assistive technology, with spoken labels on the Top and Back buttons.

8 · Construction

No.LevelRule
8.1MUSTPlain static files: one HTML page plus the shared scripts. No framework, no build step, no dependencies except web fonts with system fallbacks.
8.2MUSTNothing to attack: no database, login, forms, server code, plugins, cookies or analytics. The page stores nothing for its readers.
8.3MUSTEach shared script is the identical file on every site. It is changed in the template first, then copied out. A page missing a script loses that one control and still works.
8.4MUSTAll internal links are relative, so the folder can move to any static host unchanged.
8.5SHOULDA page of 35–100 KB. Hosted on GitHub Pages under the subject's own domain, published by commit and push.
8.6MUSTThe code is permissively licensed (MIT) and the words are reserved to their author.

9 · Color, and why it is there

Color is the most visible thing on a GYR-O page, and the name is read off it, so the reason for it has to be stated, not left for the reader to guess.

Why a color code at all

A Harvard and MIT study showed people about 400 published charts and infographics for one second each, then tested which ones they recognized when they came round again. Those with seven or more colors were recognized more often than those with two to six, and both more often than those in a single color or in grays. The difference held after pictures were taken out of the count.[1]

The study counted colors; it did not test which colors. Nothing in it favors one palette over another. The working premise of this format follows from that, and is stated as a premise, not a finding: a color code helps because it is consistent, not because of the particular colors chosen. Any code will do, provided it never changes. Two limits on the evidence: the study measured whether a picture was recognized again, not how much of its content was remembered or understood; and its readers saw each picture for one second, not for the length of a reading.

Why these colors

Since any code will do, GYR-O borrows the one nearly every reader already knows, the traffic signal, so there is nothing new to learn. Read left to right, the signal becomes a scale of effort: green, go, for the newcomer in column A; yellow, slow down and check, for the sources in column B; red, stop here only if you mean it, for the specialist in column C. Orange stands apart from the signal and belongs to the build.

There is a precedent at the busiest spot on a computer screen. When Apple rebuilt its operating system as Mac OS X, the Aqua interface it introduced at Macworld in January 2000 put three buttons in red, yellow and green at the upper left of every window, for close, minimize and zoom.[2] Macworld described them in 2001 as "resembling the lights on a traffic signal."[3] The convention was borrowed, not invented, and that is its strength: it may be the most often seen color code in daily computer use, and nobody has to be taught it. GYR-O runs the signal the other way, green first, so a page starts at go.

  2. Aqua (user interface), Wikipedia. en.wikipedia.org
  3. Henry Bortman, Watch the Traffic Lights, Macworld, 31 May 2001. macworld.com. Cited for the traffic-signal description only: the same article says yellow zooms and green minimizes, which is the wrong way round.

The rules

No.LevelRule
9.1MUSTColumn colors, left to right like a traffic signal getting harder: A green, B yellow, C red. They are fixed for good, in line with international traffic signals, and the name GYR-O depends on them. Color rides on the furniture only (keys, column rules, labels, numerals). Body text stays black, so a reader who cannot see color, or who prints, loses nothing.
9.2MUSTLight and dark themes throughout Info, both defined from the same set of color tokens. Never on the austere index view (rule 0.2). Numerals stay red on a white disc in both.
9.1aMUSTThe meaning of the name appears on every site, on a line of its own in the footer, above the copyright line and a little larger than it: GYR-O = Green · Yellow · Red · and sometimes Orange, each word led by a small swatch of its color and its first letter in bold. The four are the format’s only colors, used the same way throughout.
9.2aMUSTOrange is the color of the build. On a reader's page it appears exactly once: the footer link built by Auto-Gyro, which leads to the public Auto-Gyro page explaining how a GYR-O site is built. Everything else in orange belongs to the build pages; the working admin page itself stays unlinked.
9.3SHOULDBody 17 px, line height 1.62, about sixty characters to the line; figure captions 22 px.
9.4MUSTAmerican spelling throughout, except text quoted from a source.
9.5MUSTEvery site explains its colors. The class site carries a folded answer in column A, Why the colors?, saying in plain words what this section says, with its sources in column B, and so does any site whose subject is the format itself. On every page of every GYR-O site, the word GYR-O in the footer key (rule 9.1a) links to that answer. A site whose topic is something else does not repeat it in its own column A, which keeps to its one topic (rule 1.1).

10 · Optional parts

No.LevelRule
10.1MAYRunning record. The current issue lives at /index.html and a permanent dated copy at /YYYY-MM-DD/index.html. Dated copies are never edited again; a correction is a later issue. Each series gets its own folder.
10.2MAYFamily. An instance under another GYR-O site ends, below the footer, with a card headed ↑ One level up, naming the site above in that site's own words.
10.3MAYThe admin page (Page D). An unlinked, noindex setup sheet, styled in orange, that writes blocks of text to paste into the file. It holds nothing and has no login. Normal readers never see it.
10.4MAYArchiving. Pages sent to the Wayback Machine, success counted only when a capture dated today can be confirmed.

11 · What arrives built, and what the author brings

Arrives built, the same everywhere

  • The control strip: tabs, search, Download PDF, Dark, Phone view
  • The threshold and its mark
  • Column heads, keys and colors
  • The source-card shape and its six-part order
  • The Internal links block and its fixed wording
  • Numerals and both ways back
  • The three renderings: wide, phone, print
  • Running-record conventions, favicon, share card, domain and hosting setup

What the author brings

  • A name
  • A one-paragraph standfirst
  • The answers in A
  • Which sources go in B, and why each is cited
  • The sections in C
  • A picture

12 · Disagreements found while compiling

The sources this definition was drawn from contradict each other in these places. Each needs a decision; the rule above follows the live class page unless noted.

  1. How many shared scripts. Column C says four (phone-view, top-button, back-link, search); the README speaks of three; cite-back.js, added 14 October, makes five. Rule 8.1 is worded so it does not depend on the count.
  2. How many checks. The README says 60, the team-of-one table says 66, the Quality assurance section says 68. Rule 6.3 requires that the count be stated, so the page currently fails its own rule until these agree.
  3. Internal links: one card or two, or three. The 14 September decision was one card. Column C now says two. Column A says two cards plus a third that links the chronicle. Rule 3.2 follows column C; whether the chronicle card belongs inside the block is open.
  4. The license defect. Column A says the license arrangement on Page F "gives away more than it should" and calls it a live defect; the project log records the MIT defect closed on 26 September, and the footer now reads code MIT · words reserved. If it is closed, column A is out of date.
  5. Column B's name. The class page labels it Sources; the 26 September color note calls it References. Rule 1.5 needs one word.
  6. The rename is on the sites, but not everywhere. Since 18 October every live page, the threshold caption and the README say GYR-O, and the format is named GYR-O Pages. Still old: the folder and repository names, and the share picture, which reads Three Columns.
  7. Starting state of the index. Rule 0.4 assumes both boxes start unchecked. If either should start checked, say which.
  8. Scripts off and printing. Rule 7.3 says all three columns render with scripts off, and rule 7.2 says print carries everything. With Info unchecked, neither holds unless print and the scripts-off view ignore the boxes. This draft has print show both parts.
  9. Is 1.6 a rule at all. "Usually it is a single page" is stated as a fact about instances, not as a requirement. It is listed here as SHOULD; it could as easily be dropped.
